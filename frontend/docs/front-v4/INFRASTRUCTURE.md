# Инфраструктура frontV4

## Права и состояние

Чистые hasPermission/hasGlobalPermission/hasAnyPermission находятся в `entities/permission/model/permissions.ts`. Глобальные права и явно переданные области id/event/location/league объединяются по OR. Числовой target означает id самого объекта. Права чужой сущности и отсутствующая область не предоставляют доступ.

`entities/permission/model/editor.ts` содержит типы редактора и чистую проверку формы прав. `entities/session/model` хранит небольшую сессию и предоставляет подписываемую проверку прав. Функции login/fetchUser защищены от ответов предыдущей сессии; параллельная загрузка пользователя дедуплицируется.

Серверное состояние принадлежит TanStack Query. Формы и открытые редакторы используют React state, уведомления — отдельный shared-store. Параметры карточки/таблицы и видимости коллекций, поиск пользователей/рассылок находятся в URL; журналы сохраняют существующий URL-параметр сущности. Локальное выделение, редакторы, сортировка и пагинация сохраняют поведение соответствующего экрана.

Окна обрезки, прав, команды и номинаций принадлежат своим сценариям и отображаются через ModalPortal. Глобальный реестр модалок и его зависимость от UI-строк удалены.

## Границы

`npm --prefix frontend run check:imports` использует TypeScript AST и проверяет импорты, реэкспорты, строковые dynamic-import и import-типы:

| Слой | Локальные зависимости |
| --- | --- |
| shared | shared |
| entities | entities, shared |
| pages | pages, entities, shared |
| app | app, pages, entities, shared |

Транспорт и чистая модель прав не импортируют React/Zustand/UI. Представления не импортируют API, сессию и store уведомлений. Прямой fetch в страницах запрещён. Проверка подключена к production build.

Правила проверяют границы слоёв, а не заменяют полный анализ всех возможных циклов внутри одного слоя. Цикл API ↔ сессия устранён направлением зависимостей и явным подключением из app.

## Проверки

`test:client` сначала строго компилирует тестируемые модули в временную папку внутри frontend/node_modules, затем запускает 64 теста node:test и удаляет временные файлы. Это позволяет использовать установленные зависимости без второго механизма транспиляции. `test:api` запускает API-поднабор.

Полный TypeScript теперь проходит, включая noUnusedLocals/noUnusedParameters. Исходные 50 диагностик устранены; исторический отчёт сохранён в [typecheck-baseline.txt](typecheck-baseline.txt).

Итоговый объём проверок и границы готовности приведены в [MIGRATION.md](MIGRATION.md).
