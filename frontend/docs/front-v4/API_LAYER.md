# API-слой frontV4

## Транспорт и подключение зависимостей

- `src/shared/api/httpClient.ts`: JSON/blob, заголовки, AbortSignal, обработка HTTP и сетевых ошибок. URL, fetch, инициализация сессии, токен и реакция на истечение сессии передаются явно.
- `src/shared/api/errors.ts`: ApiError с code/status/details/cause. Сохранено совместимое error.code/message/details для имеющихся обработчиков.
- `src/shared/api/runtime.ts`, `request.ts`: настроенный экземпляр транспорта и подключаемые уведомления/обновление кеша. Сам транспорт не управляет уведомлениями.
- `src/app/configureApi.ts`, `Application.tsx`: подключение сессии, уведомлений и кеша. Транспорт не импортирует session-store и не читает localStorage/window.
- `src/entities/*/api`: endpoint, сетевые DTO и преобразования во внутренние модели. Страницы не вызывают fetch и не выбирают произвольный тип ответа API.

Первоначальный совместимый фасад `src/api` удалён после переноса всех вызывающих модулей. Исходные пути из [BASELINE.md](BASELINE.md) относятся к состоянию до переноса.

## Поведение

- Перед HTTP-запросом ожидается инициализация сессии, затем читается актуальный токен. Bearer и JSON-контракты сохранены; файлы и фотографии используют общий транспорт.
- Сессия очищается при 401 с INVALID_TOKEN/INVALID_SESSION/SESSION_NOT_FOUND только для актуального токена запроса. Поздний ответ старой сессии не сбрасывает новый вход. Одновременные ответы после очистки токена не вызывают повторную очистку.
- Сетевые ошибки и HTTP-ответы без JSON имеют единый ApiError. Отмена остаётся AbortError.
- HTTP 400 для изображения даёт null без уведомления. Кеш хранит Blob, а временный object URL принадлежит конкретному отображению и освобождается при замене/размонтировании.
- Удаление со связанными данными предлагает отдельное принудительное действие. Force-delete и restore выполняются только при выборе действия пользователем и используют актуальный токен.
- Успешные предметные мутации инвалидируют общий кеш. Auth-команды не запускают лишнее обновление старых данных; смена токена очищает кеш и пересоздаёт содержимое маршрута. Изменение прав также обновляет снимок прав текущей сессии.

## Контракты

У мероприятий, площадок, лиг, пользователей, команд, профиля/регистрации/своих команд, рассылок и итогов есть отдельные DTO/адаптеры. Внутренние модели сохраняют удобные для существующих сценариев имена; часть моделей использует camelCase, часть сохраняет прежние имена. Совпадение имени внутреннего поля с wire-полем не связывает их типы: преобразование сосредоточено в API-модуле.

API журналов и прав возвращает фиксированные предметные типы. Исторические JSON-снимки журналов преобразуются отдельными адаптерами до передачи в игровые таблицы. Результаты Socket.IO имеют отдельные протоколы и валидаторы.

Тесты проверяют HTTP-поведение, сессию, DTO и исходящие тела запросов на клиентских фикстурах. Backend не использовался как источник контрактов и не менялся; совместимость с реальным API остаётся предметом последующей интеграционной проверки.
